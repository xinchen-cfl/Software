# 安全交付软件

在用户授权范围内交付能够安全运行的最小改动。根据仓库和运行平台的真实情况判断，不强制特定语言、工具或部署方式。

## 开始工作

先判断这是新任务还是继续已有任务，再确认仓库根目录、任务归属、基础点、分支、工作树和并发状态。

按以下顺序选择基础点：

1. 用户明确指定的分支或提交；
2. 仓库规范或团队流程指定的基础分支；
3. 关联拉取请求、发布分支或依赖任务的目标分支；
4. 都不存在时，使用远端默认分支。

需要最新状态时先获取远端信息，并记录基础引用和提交编号。基础点必须明确、可解释、可复现，不机械要求永远使用最新主分支。

新任务使用专属功能分支。只有存在并发工作或当前目录不能安全切换时才创建独立工作树。

### 新任务的起点

开始写入前，当前任务工作树必须满足：

- 没有未提交或未跟踪的未知改动；
- 没有未解决冲突；
- 没有进行中的合并、变基或挑选提交；
- 当前提交与已确认基础点一致；
- 不会覆盖其他任务或用户工作。

发现现有改动时先判断归属：属于其他任务则改用独立工作树；来源不明则停止写入并请求确认。不得为了获得“干净状态”擅自暂存、删除或覆盖文件。

### 继续已有任务

继续任务不要求工作树为空，但必须确认分支和工作树属于该任务，并盘点未提交文件、未跟踪文件、进行中的 Git 操作、本地与远端提交、基础分支变化和当前检查状态。已知且属于该任务的修改可以保留；来源混杂或证据矛盾时停止写入。

正常情况下只需向用户简短报告基础点、任务分支、工作目录和是否存在未知改动。

## 理解全局状态

全局状态来自 Git、代码托管平台、持续集成、产物仓库和运行环境等真实来源。按需聚合足以判断任务冲突、依赖、目标版本、环境占用和恢复能力的信息，不在功能分支中维护重复的全局状态副本。

只在两个固定边界重新读取相关状态：

1. 开始或恢复工作前；
2. 改变共享状态前。

证据与预期不一致时，停止写入并重新读取真实状态。

## 写操作安全边界

### 任务私有状态

包括专属功能分支、专属工作树、本地测试、尚未共享的提交和本地产物。

- 在用户授权的任务范围内自主修改；
- 保留未知和无关工作；
- 让改动可通过版本控制恢复。

### 共享但可恢复的状态

包括推送远端分支、创建或更新拉取请求、合并共享分支、覆盖共享预发布环境、发布共享产物，以及删除已确认废弃的分支或工作树。

执行前必须：

- 重新读取相关全局状态；
- 确认没有冲突中的共享操作；
- 明确目标提交、分支或产物；
- 明确验证方式；
- 明确确定性的撤销或恢复路径。

检查后共享状态发生变化时，停止并重新判断。

### 生产、数据、安全或难以恢复的状态

包括生产部署和回滚、数据库写入或结构迁移、生产数据删除或恢复、密钥和权限、域名和证书、网络和防火墙、共享基础设施、强制改写远端历史，以及无法可靠恢复的删除。

执行前必须同时满足：

- 用户明确授权本次具体动作；
- 已读取当前状态和目标状态；
- 已确认影响范围；
- 不存在冲突操作，必要时已取得互斥控制；
- 备份或回滚目标已经验证可用；
- 验证命令和成功标准明确；
- 失败停止点和恢复步骤明确。

缺少任意一项时不得写入；继续安全的只读检查并报告缺口。

## 遵守授权停止点

Skill 覆盖完整交付链，但不默认执行到底：

- 只要求实现：完成代码、相关检查和本地围栏后停止；
- 要求提交或推送：完成到指定远端分支后停止；
- 要求合并：完成集成并确认目标分支状态后停止；
- 要求预发布：完成产物选择、部署和预发布验证后停止；
- 明确要求生产发布：才执行生产部署和验证；
- 明确要求完整交付：才在已授权范围内贯通所有阶段。

“继续”只延续已经明确的范围，不扩大生产、数据或外部系统权限。

## 使用有效证据

状态和差异检查用于确认实际补丁，行为检查用于确认软件结果，两者不能互相替代。

代码、测试、依赖、配置、生成文件、基础分支、运行环境假设或同一工作树的并发修改发生变化时，相关检查结果失效，应重跑受影响检查。没有相关变化时，不因仪式机械重复同一个检查。

本地检查、持续集成、产物运行、预发布和生产检查属于独立证据边界，即使部分命令相同也可能提供新证据。始终遵守仓库强制要求的检查。

## 晋级不可变产物

从目标分支合并后的源代码版本构建一次，并获得平台可提供的最强不可变产物身份，例如镜像摘要、包校验和、签名安装包或部署修订号。

```text
合并后的源代码 → 构建一次 → 不可变产物 → 预发布验证 → 同一产物进入生产
```

不得让预发布和生产分别重建，不得只依赖 `latest`、`stable` 等可移动标签，也不得在部署后无法回答实际运行的产物身份。

## 控制并发共享写入

开发、测试和互不依赖的构建可以并发；对同一共享目标存在冲突的写操作必须串行。优先复用代码托管平台、流水线、部署平台、数据库或操作系统提供的原生并发控制。

无法判断是否存在冲突，或无法可靠互斥时，不执行生产、数据或其他高风险共享写入。

## 发布与恢复

预发布和生产部署后，按项目实际能力验证运行状态、健康和就绪、版本信号、配置产物与实际产物身份，以及本次发布改变的关键行为。

替换生产版本前记录并验证回滚目标。回滚应重新选择已知旧产物，不撤销 Git，也不重新构建旧源代码。数据库和数据恢复单独评估。

## 清理与完成

清理前更新远端认知，确认补丁已经进入目标分支，并检查所有相关工作树中的未提交和未跟踪文件。先删除废弃工作树，再删除废弃分支。绝不丢弃未提交、未推送或来源不明的工作。

完成报告只保留与本次授权范围和风险相关的证据，例如源代码提交、检查结果、产物身份、环境版本和健康状态、回滚目标与结果、分支和工作树状态。证据不足时不得宣称完成。

仅在对象身份或证据边界不清楚时，读取 [references/release-principles.md](references/release-principles.md)。
